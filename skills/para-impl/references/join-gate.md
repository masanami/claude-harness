# 合流ゲート（最終応答前の未合流確認）

> 参照パスは `${CLAUDE_PLUGIN_ROOT}` 配下です（例: `${CLAUDE_PLUGIN_ROOT}/skills/para-impl/references/join-gate.md`）。Read にはプラグインの絶対パスが必要です（スキル起動時の「Base directory for this skill」を起点に解決する）。

**本スキルの実行中にサブエージェント・バックグラウンド処理を1つでも起動した場合、最終応答（Phase 10 の完了報告・中断報告を含む、あらゆるテキスト応答の確定）の前に本ゲートを必ず評価する。** 完了報告を出せるのは、決定表で「ゲート通過」に該当した場合だけである。**決定表が中断報告へ倒した場合は、その中断報告の確定自体がゲートの評価結果であり、「ゲート通過」を要件としない**（通過状態を待って永遠に再試行しない）。手順違反となるのは、**ゲートを評価せずに確定する最終応答**だけである。根拠: headless（`claude -p`）では最終応答の確定と同時にプロセス群ごと終了し、未合流のサブエージェントは道連れで強制終了されて作業ブランチに未コミット差分だけが残る。対話モードでは応答確定後も完了通知が届いて続行できるため、この差は headless でのみ顕在化する。ただし**本ゲートは実行モードの検出に依存せず常に適用する**（headless か対話かの判定を独自に行わない。常時適用が headless との挙動差を skill 側で吸収する。対話モードでの追加コストは合流確認の一手のみで無害）。

本ゲートの定義の正本は本ファイル（`references/join-gate.md`）である（SKILL.md 本文と `references/star-parallel.md` は本ファイルを参照し、独自の定義を持たない）。

## 用語

- **起動台帳**: このセッションで自分が起動したサブエージェント（Task ツール等）・バックグラウンド処理の一覧（種別・担当Issue・worktree パス／作業ブランチ、および**有限タスク／常駐サービスの区別**）。起動のたびに追記して保持する。
- **有限タスク**: 完了して**最終返却（結果）を産む前提**の起動（サブエージェント・一過性のバックグラウンド処理）。
- **常駐サービス**: **意図的に稼働し続け、最終返却を産まない前提**の起動（dev サーバ・watch プロセス等）。**最終返却を待ってはならない**（待つと永遠に合流できず、ゲートを通過できない）。
- **終端返却**: 有限タスクの返却が確定し、当該プロセスが残っていない状態の返却。**成功・失敗を問わない**（`failure`・判断待ち・permission 拒否による未実施報告などの失敗系の終端返却も含む）。ゲートの関心は**プロセス残置の有無**であり、結果の成否には関知しない（成否の処理は呼び出し元の返却処理——star 型では「worker からの返却の処理」表——が担う）。
- **合流済み**: 有限タスクは**未解消報告を含まない終端返却をこのセッションで受領した**状態（成功・失敗を問わない）。常駐サービスは**停止・後始末を実施し、停止を確認して台帳に記録した**状態（突合済み＝合流相当）。「起動に成功した」「完了通知が来るはず」「稼働中である」は合流ではない。
- **未合流**: 起動台帳に載っており、合流済みでもネスト未解消でもないもの。区別が記録されていない・判別できない起動が残っている場合は、決定表の「どの行に該当するか判定できない場合」の既定（中断報告）に従う。
- **ネスト未解消**: 有限タスクの返却は受領したが、その返却に合流ゲート伝播条項 (3) の未解消報告が含まれる状態。**合流済みとして扱わない**（台帳に「ネスト未解消」として記録する。委譲先のネストは未コミット作業ごと終了している可能性があるため、決定表のネスト未解消行が中断報告へ倒す）。

## 手順（spawn 時）

1. サブエージェント・バックグラウンド処理を起動したら、その場で起動台帳に追記する。**有限タスクか常駐サービスかの区別も記録する**。
2. **起動直後にテキストで応答を確定しない**。「完了を待ちます」「通知が来次第続行します」等の待機宣言をテキスト応答として出力した時点で、headless ではセッションが終了し起動済みエージェントは全滅する。待機宣言は注意書きではなく**手順違反**として扱う。完了通知・返却が届くまで**ツール呼び出しを続けてターンを維持する**（結果取得ツールでのブロッキング待機、または状態確認のポーリングを合流まで繰り返す）。**常駐サービスにはこの待機を適用しない**（最終返却を産まないため。停止確認による突合は決定表の常駐サービス行で行う）。

## ネストへの伝播（spawn プロンプト条項）

起動台帳が把握できるのは**自分が直接起動したものだけ**である。委譲先（`ticket-worker`・`feature-implementer` 等）が自身でさらにサブエージェントや常駐サービスを起動する場合、そのネストの解消は台帳では検査できない。そのため、サブエージェントへ委譲する spawn プロンプトには、次の**合流ゲート伝播条項**を逐語で含める（Task ツールを持たないエージェントへの委譲でも含めてよい・害はない。含めるか迷った場合は含める）。**ネストの解消は各委譲先が本条項で保証する**——委譲先からの**条項 (3) の未解消報告を含まない終端返却**（成功・失敗を問わない）の受領は、委譲先がネストを解消済みであることを含意する。**未解消報告を含む返却は合流済みとして扱わず、台帳に「ネスト未解消」として記録する**（決定表のネスト未解消行が親の中断報告へ倒し、委譲先が報告した未解消の一覧・実状態を転記する）:

```text
【合流ゲート伝播条項】あなたが Task ツール等でサブエージェントを起動する場合、またはバックグラウンド処理・常駐サービス（dev サーバ等）を起動する場合:
(1) 最終返却を確定する前に、起動したものをすべて解消する（有限タスクは未解消報告を含まない終端返却の受領〔成功・失敗を問わない。返却が確定しプロセスが残っていないもの〕、常駐サービスは停止・後始末の確認）。
(2) 「完了を待ちます」等の待機宣言を最終返却にしない。解消が済むまで、または (3) の解消不能の判断に至るまで、ツール呼び出しを続けてターンを維持する。
(3) 解消できない場合は、未解消の一覧と実状態（未コミット差分の所在を含む）を返却に明記する。
(4) 子の返却に (3) の未解消報告が含まれる場合は、その子を解消済みとして扱わず、自分の返却にその未解消の一覧・実状態を転記して上へ伝える（未解消報告を含まない返却にしない）。
(5) さらに委譲する場合は、この条項を委譲プロンプトへそのまま含める。
```

## 手順（最終応答の直前）

起動台帳と合流済みの記録を突き合わせ、次の決定表で分岐する。**各行の状態は互いに排他であり、どの状態も高々1行にだけ該当する**（1〜6行目は台帳と実状態の突き合わせが成立していることが前提。成立しない場合に該当するのは最終行だけ）。**どの行に該当するか判定できない場合は、突き合わせ不能として最終行（中断報告）へ倒す**。受領の見込みは**実状態の確認で判定し、待機・ポーリングの回数や経過時間だけを根拠に判定しない**（結果取得のタイムアウトは「結果がもう来ない」ことを意味しない。Phase 4〜9 を実行中の worker は長時間・多数回の待機にまたがって正当に稼働し続ける）。再試行上限（**3回を目安**）は、**稼働確認も結果取得もできない場合の確認試行にだけ**適用する:

| 状態 | 動作 |
|---|---|
| 起動台帳が空（1つも起動していない） | ゲート通過。そのまま最終応答へ |
| 未合流 0件かつネスト未解消 0件（起動台帳が1件以上あり、有限タスクはすべて終端返却を受領済み・常駐サービスはすべて停止確認済み） | ゲート通過。そのまま最終応答へ |
| 未合流の有限タスクが1件以上で、受領の見込みがある（稼働を確認できる、または結果取得の待機・タイムアウトが続いているだけ） | 最終応答を確定せず、ツール呼び出しで合流を続ける。合流できたら本ゲートを最初から再実行する（常駐サービスの停止は、有限タスクの合流がすべて済むまで行わない） |
| 未合流の有限タスクが1件以上のまま、受領の見込みがない（稼働確認も結果取得もできない状態が、確認の再試行上限まで続いた） | 合流を断念し、完了報告ではなく**中断報告**（下記の出力契約）へ倒す |
| 未合流の有限タスクは0件で、停止確認の済んでいない常駐サービスが1件以上 | 常駐サービスを停止・後始末し、停止を確認して台帳に記録してから本ゲートを最初から再実行する。**最終返却は待たない**。停止を確認できない場合は**中断報告**へ倒す |
| 未合流 0件のまま、ネスト未解消として記録された起動が1件以上 | ゲート通過にせず、**中断報告**へ倒す（委譲先が報告した未解消の一覧・実状態を転記してエスカレーションする） |
| 起動台帳と実状態を突き合わせられない（台帳の欠落・コンテキスト要約による消失・台帳に載っていない合流記録がある〔合流済み件数が起動台帳件数を上回る〕等） | 未合流 0件とみなさず、**中断報告**へ倒す（検査不能を0件に丸めない） |

- 未合流 0件（起動台帳が空の場合を含む）は**正常経路**である。0件であることを検査不能・失敗と混同しない。
- **一部のエージェントが合流済みでも、未合流が1体でも残っていればゲートは通過しない**（部分合流を全合流と報告しない）。
- **どの行から中断報告へ倒す場合も、確定の前に停止確認の済んでいない常駐サービスの停止・後始末を試みる**（headless では報告の確定と同時にプロセス群が終了し、後始末の機会が失われるため）。停止の成否にかかわらず結果を中断報告の常駐サービス項目に記録し、**停止試行の失敗は中断報告の確定を妨げない**（成功するまで再試行しない）。

## 中断報告の出力契約

合流を断念した場合、完了報告の代わりに次の項目を**すべて**含む中断報告を最終応答にする（不明な項目は「不明」と書く。省略・推測で埋めない）:

- 未合流のサブエージェント・処理の一覧（種別・担当Issue・起動時の指示概要）
- 常駐サービスの一覧と確定前の停止試行の結果（停止確認済み／停止失敗の別。停止失敗分は種別・停止と後始末の手順を書く。無ければ「なし」と書く）
- 委譲先から報告されたネスト未解消の一覧（合流ゲート伝播条項 (3) の報告の転記。無ければ「なし」と書く）
- 未コミット差分の所在（worktree パス・作業ブランチ）
- 合流済みエージェントの成果（PR URL 等）と未合流分の切り分け
- 回収手段（`--resume` での再開・worktree 内の差分確認手順など、次に人間または親セッションが取るべき手順）
