## 記録モード（決定 → ADR 1件）

1つの恒常的な設計決定を ADR として記録する。

> **本ファイルの前提**: 起動引数の解釈は SKILL.md 側で完了している前提で読むこと。**何を ADR にするかの線引き（3条件）・置き場と採番・構成とステータス・改訂の扱い・ドキュメントマップへの反映は SKILL.md の「共通規約」が正本**であり、本ファイルには複製しない。

### Step R1: 対象の把握と線引きゲート

1. `CLAUDE.md` を読み、SKILL.md「共通規約」に従って **ADR の置き場を解決する**（以降 `<ADR置き場>`。既定 `docs/adr/`）。あわせて関連する既存ドキュメントを把握する。以降の採番・書き出し先・報告はすべてこの解決値を使う。
2. 記録対象の決定を1文で言い切れる形に整理する（例: 「認可はロールベースではなくポリシーベースで実装する」）。1文にまとまらない場合は**複数の決定が混ざっている**ため、決定ごとに分割し、それぞれを別 ADR の候補として扱う。
3. **各候補に SKILL.md「共通規約」の3条件（恒常性・非自明性・選択性）を当てる**。3条件を満たさない候補は ADR にせず、委ね先（Issue・保証台帳・コード）を明示してユーザーに伝える。
   - **すべての候補が条件を満たさなかった場合は、ADR を作らずにここで終了する**（「呼ばれたから何か書く」をしない）。この場合は Step R5 の「**B. ADR を作成しなかった場合**」の報告を出す。判定理由（候補ごとに3条件のどれを満たさなかったか）と委ね先を必ず添える。
   - **そもそも候補を抽出できなかった場合**（入力に決定が含まれていない）は、「候補0件」として報告する。「候補はあったが条件を満たさなかった」と混同しない。

### Step R2: 決定内容の確定

決定が**すでに確定している**場合（人間の判断済み・上流の設計で決定済み・実装がすでにその方針で動いている等）は、その内容をそのまま記録する。裏取りとして関連コード・Issue・PR を確認し、記録内容と実態が食い違う場合は**記録を実態に合わせず、食い違いをユーザーに提示して確認する**（ADR が実態と乖離した規範を宣言するのを防ぐため）。

- **裏取りができなかった場合**（該当コードを特定できない・Issue/PR にアクセスできない）は、「実態と一致することを確認済み」と書かない。**「未確認」として扱い**、Step R4 の「未検証の前提」に何を確認できなかったかを明示する（確認していないことを「食い違いなし」と同一視しない）。

決定が**まだ確定していない**場合は、確定させてから記録する。ADR は「決めたことの記録」であり、未決の議論を書く場所ではない:

1. 既存パターン・制約を調査する（関連コード、`CLAUDE.md` の規約、既存 ADR、フレームワークの制約）。
2. **選択肢を最低2案**、それぞれの pros/cons と推奨案・推奨理由を提示し、ユーザーに採用案を選んでもらう。
3. 決着しない論点が残る場合は、**その論点を「未決事項」として ADR 内に明示的に残す**（決めたふりをしない）。未決事項には「何が分かれば決められるか」を必ず添える。

### Step R3: 既存 ADR との突き合わせ（新規作成か改訂か）

`<ADR置き場>` の既存 ADR を一覧し、**同じ問いを扱う ADR が既にあるかを確認する**。

- **一覧・読み取りに失敗した場合は停止する**（ディレクトリは存在するが読めない等）。既存 ADR を「無い」と誤認すると、重複 ADR の作成や、採番のやり直しによる既存ファイルの上書きが起きる。**「読めなかった」を「0件」として扱わない**（SKILL.md「共通規約」の採番規約）。
- **同じ問いを扱う ADR があり、決定内容も現行のまま変わらない**（＝記録しようとしている内容が既存 ADR に既出で、追記すべき差分が無い） → **新規作成も改訂もしない**。Step R5 の「**B. ADR を作成しなかった場合**」を、理由 `既存 ADR NNNN に既出（内容一致）` として出し、**既存 ADR のパスを参照先として報告する**（新規作成した ADR としては報告しない）。
- **同じ問いを扱う ADR があり、決定内容が変わる** → 新規作成せず、SKILL.md「共通規約」の改訂ルールに従って処理する（同じ問いへの答えの更新なら元 ADR への追記改訂、問い自体が変わっているなら新規作成＋元 ADR を `Superseded by ADR NNNN` に）。どちらに当たるかの判断と根拠を報告に残す。
- **無い** → 新規作成する。共通規約の採番ルールで番号を決め、`NNNN-slug.md` のパスを確定する。

### Step R4: 執筆

> **参照ファイルの読み出し（重要）**: 参照ファイルは導入先プロジェクトではなく**プラグイン配下**にある。プラグイン配下は導入先プロジェクトの作業ディレクトリの外にあるため、Read ツールでの読み出しは利用側に allow 設定が無いと拒否される（headless 委譲では許可する相手がいないため、既定で読めない）。読み出しは allowlist 済みの配送経路`claude-harness-run read-plugin-doc "skills/create-adr/templates/adr.md"`（プラグインルート相対パス）で行い、stdout に出た本文を使う。**非0 終了は「読まなくてよかった」ではない** — 本文を得られていないまま手順を推測して続行せず、stderr のメッセージを添えてその場で停止し報告すること（読めないまま完走すると、書式や停止条件だけが外れた成果物が「成功」に見える）。**exit 0 でも終端マーカー `=== read-plugin-doc END ... complete ===` が無ければ本文は完結していない** — `MORE` マーカーが出ていれば示された `--from-line` で続きを取得し、END も MORE も無ければ出力が切り詰められたとみなして同様に停止すること。`=== read-plugin-doc ... ===` の行と `read-plugin-doc:` で始まる行は配送の制御情報であり本文ではない（テンプレートを埋めて書き出す際に成果物へ含めない）。`claude-harness-run: command not found` の場合のみ Read ツールへフォールバックし、スキル起動時にコンテキストへ与えられる「Base directory for this skill」を起点に `<base>/templates/adr.md` として解決する（Read も拒否された場合は同様に停止して報告し、ランチャー導入を案内すること）。

`${CLAUDE_PLUGIN_ROOT}/skills/create-adr/templates/adr.md` を読み込み、Step R1〜R3 の内容で埋めて **`<ADR置き場>/{NNNN}-{slug}.md`** へ書き出す（改訂の場合はテンプレートの「改訂」節のみを既存ファイル末尾へ追記する）。

執筆時の規律:

- **決定は断定形で書く**。「〜が望ましい」「〜を検討する」ではなく「〜とする」。後から読んだエージェントが従うべき規範として読めること。
- **代替案は「却下した理由」が本体**。案の説明を並べるだけでは再燃を防げない。
- **背景には決定時点の前提を書く**。前提が変われば決定を見直せるようにするため（「将来の見直し条件」として帰結に書いてもよい）。
- 事実として確認していないことを推測で書かない。裏が取れていない前提は「未検証の前提」として明示する。
- 該当しないセクション・メタ情報の行は削除する（空欄で残さない）。

### Step R5: ドキュメントマップの反映と完了報告

1. SKILL.md「共通規約」の「ドキュメントマップへの反映」に従う（そのプロジェクトで初めて ADR を作成した場合のみ）。
2. **ADR を作成・改訂したかで報告の様式が変わる**（SKILL.md「出力契約: 「ADR なし」は正常な結果」）。次の A / B のどちらかを出す。パスはすべて Step R1 で解決した `<ADR置き場>` を使い、`docs/adr/` を固定で書かない。

**A. ADR を作成・改訂した場合**

```text
## ADR 作成 完了

- ADR: <ADR置き場>/{NNNN}-{slug}.md（新規作成 | 既存 ADR への改訂追記）
- 決定: {1文の要約}
- ステータス: {Accepted | Amended | Superseded by ADR NNNN | Rejected}
- ADR にしなかった候補: {候補と、3条件のどれを満たさなかったか・委ね先。他に候補が無かった場合は「なし（他の候補なし）」、全候補を ADR 化した場合は「なし（全候補を ADR 化）」}
- 未決事項: {ADR 内に残した未決事項。無ければ「なし（0件）」}
- CLAUDE.md ドキュメントマップ: {追記した | 既に行がある | 表が無いため未追記}

次のステップ:
- 内容を確認のうえ /commit でコミットしてください（本スキルはコミット・PR 作成を行いません）
```

**B. ADR を作成しなかった場合**（候補0件／3条件を満たす候補が無い／既存 ADR に既出）

**ADR パス・ステータスの行は出さない**（作っていないものを報告しない）。「新規作成した ADR」としても報告しない。代わりに作らなかった理由を出す:

| 理由 | 該当する状況（判定した箇所） |
|---|---|
| `入力から恒常的決定の候補を抽出できなかった（候補0件）` | Step R1: そもそも候補が無い |
| `3条件を満たす候補が無かった` | Step R1: 候補はあったが恒常性 / 非自明性 / 選択性 のいずれかを欠く |
| `既存 ADR NNNN に既出（内容一致）` | Step R3: 同じ問いを扱う ADR があり、追記すべき差分が無い |

```text
## ADR 作成 完了（ADR なし）

- ADR: なし（作成・改訂していません）
- 理由: {上表のいずれか}
- 判定した候補: {候補ごとに「{候補の要約} — 恒常性 / 非自明性 / 選択性 のどれを満たさなかったか → 委ね先」。候補0件なら「なし（0件）」}
- 既出の参照先: {理由が「既存 ADR NNNN に既出」の場合のみ: <ADR置き場>/{NNNN}-{slug}.md と、内容一致と判断した根拠。該当しなければこの行を出さない}
- CLAUDE.md ドキュメントマップ: 未追記（ADR を作成していないため）

補足:
- 「作らなかった」は正常な結果です。恒常的決定でないものを ADR にすると、記録が増えて読まれなくなります。
- 委ね先（Issue・保証台帳・コード）に記録が残っていることを確認してください。

次のステップ:
- {既出の場合: 既存 ADR の内容が現状と食い違う場合は、共通規約の改訂ルール（追記改訂 / Superseded）で処理してください}
- 記録すべき決定が他にある場合は、その決定を指定して再実行してください
```
