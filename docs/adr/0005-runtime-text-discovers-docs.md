# ADR 0005: 実行時テキストは `CLAUDE.md` の任意節に単独依存せず、探索へフォールバックする

- **ステータス**: Accepted
- **日付**: 2026-09-20
- **関連**: Issue #241（本 ADR の宣言元）, #237 / #239 / PR #240（`CLAUDE.md.template` の棚卸し）

## 背景

PR #240（Issue #237 の棚卸し）で、`/init-project` が生成する `CLAUDE.md` から「ドキュメントマップ」「開発原則」「技術スタック」「ディレクトリ構成」の各節が削除された。コードベースから導ける内容、および検証できない一般論を実行時に常時ロードさせないための決定であり、その判断自体は妥当である。

一方、`skills/` `agents/` の実行時テキストには「`CLAUDE.md` のドキュメントマップから設計書を読む」「`CLAUDE.md` を読み、開発原則・技術スタック・ディレクトリ構成を把握する」と書かれた箇所が残っていた（実測 10 ファイルが `ドキュメントマップ` に、12 ファイルが `開発原則` に言及）。**新規生成物ではこれらの節が存在しないため、指示された入口が1つも無い状態になる。**

この破れ方は沈黙する。「節が読めなかった」と「設計ドキュメントが存在しない」はモデルから区別できず、突合せを丸ごと飛ばした結果が `確認済み` として返る。生成物はテンプレート追従を持たないため、旧世代（節を持つプロジェクト）と新世代が同時に存在し続ける点も条件を複雑にする。

## 決定

**実行時テキストは `CLAUDE.md` の任意節を唯一の入口にしない。「節が在れば使い、無ければ探索する」の順で書く。**

1. **設計ドキュメントへの到達**は、節ではなく `docs/` 配下の探索が担う。探索の範囲は `scripts/analyze-project.sh` の `docs.designDocs` に揃える（`architecture` / `system-design` / `domain-model` / `erd` / `schema` / `database` / `api-spec` / `openapi` をファイル名に含む `docs/**/*.md`）。加えて `docs/adr/`（設計判断記録）と `docs/features/`（機能仕様）を読む。
2. **開発原則・技術スタック・ディレクトリ構成**は `CLAUDE.md` に書かれないのが既定と明記し、マニフェストと実ディレクトリから得る。**記載が無いことを理由に停止しない。**
3. **「節が無い」を「対象が無い」と読み替えることを明示的に禁じる。** 禁止文を書かないと、到達不能が「不在」として成功報告に化ける（この読み替えこそが沈黙する失敗の本体であり、禁止文は行動を変えるため実行時テキストに残す側に落ちる → `docs/plugin-path-conventions.md` (h)）。
4. **ADR 置き場の解決**も同じ順で行う: `CLAUDE.md` の記載 → `docs/` 配下の `adr` / `decisions` / `decision-records` の探索 → 既定 `docs/adr/`。記載の不在は別パスの証拠でも、停止の理由でもない。
5. **旧世代の生成物を切り捨てない。** フォールバックは「節が在ればそれを使う」を保ったうえでの**追加**であり、置換ではない。`create-adr` のドキュメントマップ追記も、節を持つプロジェクトに対しては従来どおり動く。

規約の本文は、共通の参照先へ集約せず**各実行時ファイルへインラインで書き切る**（集約すると headless 委譲で1バイトも届かない → `docs/plugin-path-conventions.md` (b)(f)）。

## 検討した代替案

| 案 | 不採用の理由 |
|---|---|
| **`CLAUDE.md.template` にドキュメントマップ節を復活させる** | #237 の棚卸しを巻き戻す。「作成予定」の行が未実在パスを常時ロードさせる問題が再発し、`docs/` を走査すれば得られる情報を人手で二重管理することになる |
| **`analyze-project.sh` の結果を実行時に参照させる** | 同スクリプトは `/init-project` の初期化時に1回走る設計で、レビュー・実装の各エージェントが毎回起動する前提になっていない。探索そのものは Glob 数回で足りる |
| **共通の参照ファイル（`skills/_shared/`）へ集約し各所は1行参照** | 参照先は headless では既定で読めず、規約が最も必要な文脈で届かなくなる（実測 → (b)）。逐語コピーは冗長に見えて到達性の荷重を負っている |
| **「節が無ければスキップ」で degrade させる（従来の暗黙の挙動）** | スキップが既定経路になる。突合せを飛ばした結果が成功として返るため、検出されない |

## 帰結

- 新規生成物（節なし）・旧世代（節あり）の双方で、設計ドキュメントへの到達手段が実行時テキストに明記される。
- 実行時テキストは1ファイルあたり数行増える。(h) の判定軸では、これらは行動を変える文であり残す側に落ちる。
- `scripts/tests/test-doc-discovery-fallback.sh` が構造不変条件を固定する: 到達を責務に含むファイルが不変コアを持つこと、`ドキュメントマップ` に言及するファイルの全称条件（到達手段を持つか、節の不在を既定として扱う許可リストに属するか）とその**逆方向**、旧来の硬直依存 `ドキュメントマップから` の不在、ADR 置き場の既定フォールバック、旧世代経路の残存。
- **本 ADR は実行時ファイルから参照しない**（(f) の参照禁止）。規範は各実行時ファイルにインラインで書き切ってある。
